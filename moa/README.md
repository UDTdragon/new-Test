# 모아

좋은 정보를 모아두고 필요할 때 다시 찾는 개인용 정보 보관함의 첫 화면입니다.

## 실행

PC에서는 [Node.js](https://nodejs.org/)의 LTS 버전을 설치하세요. 이미 설치되어 있으면 다시 설치할 필요가 없습니다.

1. 프로젝트 압축 파일을 풀고, VS Code에서 **파일 → 폴더 열기**로 `package.json`이 들어 있는 **`new-Test/moa` 폴더**를 엽니다. 저장소 폴더 `new-Test`를 열었다면 터미널에서 먼저 `cd moa`를 실행하세요.
2. VS Code의 **터미널 → 새 터미널**을 엽니다.
3. 아래 명령을 순서대로 실행합니다. `npm ci`는 처음 실행하거나 의존성이 바뀌었을 때 필요합니다.

```sh
npm ci
npm run dev
```

4. 터미널에 표시되는 `Local` 주소를 브라우저에서 엽니다. 실행 중에는 터미널을 열어두세요. 종료는 `Ctrl+C`입니다.

VS Code의 Live Server 대신 `npm run dev`로 실행하세요. React·TypeScript 소스는 Vite 개발 서버를 통해 실행됩니다.

프로덕션 빌드는 `npm run build`, 빌드 결과 확인은 `npm run preview`로 실행합니다. 기본 개발 서버 포트는 5173입니다. GitHub Pages의 저장소 하위 경로에서도 사용할 수 있도록 상대 경로로 빌드합니다.

클라우드 작업 환경에서는 `/workspace/new-Test/moa`에서 실행하고, npm 기본 캐시 경로에 쓸 수 없다면 `npm ci --cache /tmp/moa-npm-cache`를 사용합니다.

## GitHub Pages 접속

저장소의 `.github/workflows/deploy-pages.yml`이 `main` 변경 시 이 폴더에서 의존성 설치·빌드를 실행하고 `dist`를 GitHub Pages에 배포합니다. 최초 Pages 활성화 방법은 [저장소 안내](../README.md#웹사이트로-접속)를 참고하세요.

배포가 완료되면 **https://udtdragon.github.io/new-Test/** 로 접속합니다. Vite의 상대 경로 설정으로 저장소 하위 주소에서도 글꼴과 이미지가 로드됩니다.

## 포함된 기능

- PC·태블릿·모바일 반응형 카드 목록과 목록 보기
- 제목, 메모, 태그, 링크 이름·주소 검색 및 분류 필터
- 즐겨찾기와 저장일·제목 정렬
- 정보 추가, 상세 보기, 수정, 삭제, 원문 열기
- 링크 없이 제목·메모만 저장 가능. 관련 링크는 선택 사항이며, 빈 입력 행은 저장에서 제외
- 카드 하나에 여러 관련 링크 저장: 링크별 이름·URL 입력, 추가·삭제, 상세 창에서 개별 열기
- 로그인 없는 Supabase 공용 보관함 저장 및 새로고침 후 복원
- 기본 카테고리 5개: 디자인, 개발, 꿀팁, 영상, 기타
- 카테고리 관리: 추가, 이름 변경, 순서 변경, 기본 썸네일 선택, 삭제 시 정보 이동
- 저장·수정·상세 창은 주변 배경을 눌러도 닫히지 않으며, 닫기·취소 버튼 또는 Escape로 닫기
- 키보드 검색 단축키 `Ctrl+K` / `⌘K`

첫 방문에는 공용 보관함을 불러옵니다. 아직 shared 행이 없으면 빈 보관함으로 시작하며 첫 저장 시 생성합니다. 카드 표지와 글꼴은 프로젝트에 포함되어 있어 외부 이미지·글꼴 요청이 필요하지 않습니다.

## 카테고리 관리

목록 위의 **카테고리 관리** 버튼을 누르세요. 이름을 수정하거나 위·아래 화살표로 순서를 바꿀 수 있습니다. **카테고리 추가**로 새 분류를 만들고 5가지 이미지 중 기본 썸네일을 선택할 수 있습니다. 이름은 중복 없이 30자 이내로 입력하며, ‘전체’는 공통 필터로 사용됩니다.

저장된 정보가 있는 카테고리를 삭제하면 정보를 옮길 카테고리를 먼저 선택합니다. 제목·메모·링크·태그·즐겨찾기는 유지됩니다. 최소 1개 카테고리는 남겨야 합니다. 모든 변경은 **변경사항 저장**을 눌렀을 때 함께 적용되며, 취소하면 이전 상태를 유지합니다.

## 현재 썸네일

디자인·개발·꿀팁·영상·기타에 맞춰 제작한 이미지 5개가 `src/assets/categories/`에 포함되어 있습니다. 새 정보와 기존 정보 모두 해당 카테고리의 기본 이미지를 자동으로 표시합니다. 링크 없이 저장한 메모에도 적용됩니다. 정보의 카테고리나 카테고리의 기본 썸네일을 변경하면 표지도 함께 바뀝니다.

실행 중 이미지 생성 비용은 없으며, 이미지 업로드나 링크의 대표 이미지 자동 수집 기능은 아직 구현하지 않았습니다.

## 현재 저장 방식

`public.moa_public_test_library`의 `id = 'shared'` 행을 REST API로 읽고 저장합니다. `data`는 `{ "version": 3, "categories": [...], "items": [...] }` 형태의 JSONB입니다. Supabase Auth는 사용하지 않습니다. anon 역할에 해당 행의 SELECT/INSERT/UPDATE 권한 및 RLS 정책이 필요합니다. 테이블의 id에는 고유 제약이 있어야 합니다. 이미 있는 데이터가 잘못된 형식이면 덮어쓰지 않고 오류를 표시합니다.

GitHub Variables의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`가 배포 빌드에 주입됩니다. 로컬 개발에서는 `moa/.env.local`에 같은 변수를 설정합니다. publishable 키만 사용하며 service-role 키는 사용하지 마세요.

불러오기가 완료되기 전에는 편집할 수 없습니다. 저장은 한 번에 하나씩 수행하며, 읽었던 JSONB 값과 서버 값이 같은 경우에만 수정합니다. 동시 수정 충돌이나 권한 오류는 저장 실패로 표시합니다. 네트워크 오류는 **저장 재시도**로 재시도하고, 충돌 시에는 **보관된 임시본 내려받기**로 JSON을 보관한 뒤 새로고침해 최신 정보를 확인하세요. 다른 사용자의 변경은 새로고침 시 반영됩니다. 전체 JSONB를 비교하는 방식이므로 큰 보관함에서는 요청 URL 길이 제한을 고려하여 추후 서버 RPC로 전환할 수 있습니다.

기존 `moa-library-v3`, `moa-bookmarks-v2`, `moa-bookmarks-v1`은 수정·삭제하지 않습니다. 같은 브라우저·주소에서 **기존 브라우저 정보 가져오기**를 누르면 기존 카테고리와 카드를 공용 보관함에 합칩니다. 같은 이름의 카테고리는 연결하고, 내용이 다른 카드는 별도 ID로 보존합니다. 동일한 정보를 반복해서 가져와도 중복 추가하지 않습니다. 이전 ‘생산성’은 ‘꿀팁’, ‘라이프’는 ‘기타’로 연결하며 단일 URL은 링크 1개로 변환합니다.

저장할 공용 데이터는 별도 `moa-public-library-draft-v1` 키에 임시 보관됩니다. 브라우저 저장소가 차단되면 현재 화면에서 임시본을 내려받을 수 있습니다. 공용 저장 실패를 성공으로 표시하지 않으며, 브라우저 원본은 그대로 유지합니다.

검증: Node.js 24에서 `npm test`로 API 요청, 오류/충돌, 브라우저 데이터 이전을 확인하고 `npm run build`로 TypeScript 및 배포 빌드를 확인합니다.
